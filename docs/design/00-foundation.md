## 1. 전제 조건

| 항목 | 결정 |
|---|---|
| 장르 | 1인칭 오픈월드 액션 RPG (사이버펑크) |
| 엔진 | Unity 6 LTS |
| 렌더 파이프라인 | **URP** (권장, 아래 근거) |
| 1차 목표 | **버티컬 슬라이스**: 한 구역을 완성도 있게, 플레이 30~60분 분량 |
| 역할 분담 | 개발(코드·구조·데이터): Claude / 기획 보조·검수·플레이 테스트: 사용자 |
| 플랫폼 | PC (Windows), 키보드·마우스 우선, 게임패드는 2순위 |

### 작업 방식에 관한 제약
- 이 개발 환경(클라우드 컨테이너)에는 **Unity 에디터가 없습니다.** 저는 C# 코드, 에디터 스크립트, 데이터(ScriptableObject), 문서를 작성하고 커밋합니다. **실제 실행과 플레이 테스트는 사용자 PC의 Unity에서** 이뤄집니다.
- 그래서 다음을 지킵니다.
  - 씬과 프리팹을 손으로 배치하지 않아도 되도록 **에디터 메뉴 한 번으로 테스트 씬을 자동 생성**하는 스크립트를 제공합니다.
  - 마일스톤마다 "이렇게 테스트하세요" 체크리스트를 남깁니다.
  - 버그 리포트는 콘솔 로그와 재현 순서를 받는 형식으로 합니다.

### URP를 권장하는 이유
- 네온과 블룸, 안개 같은 사이버펑크 룩은 URP의 포스트 프로세싱과 데칼만으로도 충분히 낼 수 있습니다.
- 에셋 스토어 에셋 호환성이 가장 높고 PC 사양 부담이 적습니다.
- HDRP는 더 사실적이지만 무겁고 설정이 복잡해서 슬라이스 단계에는 과합니다.

`[결정 필요]` Unity 버전(6000.x LTS)과 URP 사용에 동의하시나요?

## 2. 하이 콘셉트 (초안)

> **"몸을 빌려 쓰는 도시에서, 빚을 갚을 것인가 판을 뒤엎을 것인가."**

- **가제:** `LEASED` (가칭, 다른 후보는 §8에)
- **배경:** 2080년대, 해안 수직 거대도시 **"네오 부산(Neo-Busan)"**. 산비탈 달동네 위로 기업 아콜로지가 쌓이고, 항만은 밀수와 데이터 거래의 중심지입니다.
  - 서울을 모티브로 한 사이버펑크는 흔하지만, 비탈길·항구·층층이 쌓인 동네를 가진 부산은 **수직 탐험**과 잘 맞고 개성도 뚜렷합니다.
- **주인공:** 기업에서 **사이버웨어를 리스(임대)** 받아 몸에 단 용병. 할부를 못 내면 기업이 임플란트를 **원격으로 비활성화하거나 회수**합니다.
- **핵심 갈등:** 돈(빚)과 자유(해킹으로 리스 DRM 해제), 그리고 사람(동료와 세력) 사이의 선택입니다.

> 이 설정은 시스템과 직접 연결됩니다. 빚은 경제 시스템이 되고, 리스 DRM은 해킹과 성장 시스템이 되며, "누구 편에 설 것인가"는 선택과 평판 시스템이 됩니다.

`[결정 필요]` 배경(네오 부산)과 주인공 설정(리스 사이버웨어와 빚)이 마음에 드시나요? 다른 방향을 원하시면 알려주세요.

## 3. 핵심 기둥 (Design Pillars)

네 가지 재미 축(전투, 해킹·잠입, 스토리·선택, 탐험·성장)을 **세 개의 기둥**으로 묶습니다. 기능을 추가할지 판단할 때 "이 기능이 기둥을 강화하는가?"를 기준으로 삼습니다.

### 기둥 1. 모든 문에는 세 개의 열쇠가 있다
**전투 · 해킹 · 잠입**
- 모든 목표에 최소 3가지 접근이 있습니다: **정면 돌파**(총·근접), **넷러닝**(원격 해킹), **우회**(잠입·대화·환경 이용).
- 세 방식은 서로 섞입니다. 예를 들어 카메라를 해킹해 끄고, 잠입으로 들어간 뒤, 들키면 전투로 전환합니다.

### 기둥 2. 몸이 곧 빌드다
**성장**
- 레벨업 수치보다 **사이버웨어 장착**이 플레이 방식을 바꿉니다. 이중 점프 다리, 단분자 와이어 팔, RAM 확장 OS 등이 예입니다.
- 리스 설정 덕분에 **강력한 임플란트에는 대가**(빚, 기업 추적)가 따릅니다.

### 기둥 3. 도시는 기억한다
**스토리 · 선택 · 탐험**
- 선택은 **세력 평판**, **구역 상태**(경비 강화, 상점 폐쇄 등), **NPC의 반응**으로 되돌아옵니다.
- 탐험 원칙은 **"넓이보다 밀도"**입니다. 작은 구역을 수직으로 촘촘하게 만들고, 숨은 경로와 데이터 조각, 사이드 의뢰를 곳곳에 둡니다.

## 5. 버티컬 슬라이스 범위

### 포함 (Must)
| 영역 | 내용 |
|---|---|
| 구역 | **"영도 하역지구"** 1곳. 약 250×250m, 지상·골목·옥상·지하 3~4층 구조 |
| 이동 | 걷기, 달리기, 웅크리기, 슬라이딩, 벽 오르기(맨틀), 이중 점프(임플란트) |
| 전투 | 무기 3종(권총, 산탄총, 근접 블레이드), 히트스캔 사격, 반동, 부위별 피해, 장갑 |
| 적 AI | 3종: 일반 경비, 중장갑병, 적 넷러너(플레이어를 역해킹) |
| 잠입 | 시야 원뿔, 경계 단계(무경계 → 의심 → 수색 → 전투), 은신 제압, 시체 숨기기 |
| 해킹 | 스캔 모드, RAM 기반 퀵핵 4종(카메라 차단, 주의 분산, 과열, 무기 오작동), 장치 해킹(문, 포탑) |
| 성장 | 사이버웨어 슬롯 5부위, 임플란트 8종, 인벤토리, 상점, 리퍼닥 |
| 서사 | 메인 의뢰 1개(결말 분기 2~3개), 사이드 의뢰 2개, 대화 트리와 능력 체크 |
| 세력 | 2개 세력과 평판 수치. 평판에 따라 대화, 가격, 적대 여부가 바뀜 |
| 시스템 | 저장/불러오기, 일시정지, 설정(감도, 볼륨, 키 바인딩) |

### 제외 (Won't, 슬라이스 이후 검토)
차량, 다중 구역 스트리밍, 낮/밤 사이클, 제작(크래프팅), 성우 음성, 로맨스, 멀티플레이, 경찰 수배 시스템

> 제외 목록이 기능 목록만큼 중요합니다. 오픈월드는 범위가 커지다 실패하는 경우가 가장 흔합니다.

## 6. 기술 설계 개요

### 사용 패키지
- **Input System** (새 입력 시스템), **Cinemachine 3** (카메라 흔들림 등 연출용), **AI Navigation** (NavMesh), **TextMeshPro**
- Addressables는 슬라이스 후반에 필요해지면 도입합니다.

### 아키텍처 원칙
1. **데이터와 로직 분리:** 무기, 임플란트, 퀵핵, 적, 아이템, 대화를 **ScriptableObject**로 정의합니다. 밸런스를 바꿀 때 코드를 고치지 않아도 됩니다.
2. **컴포넌트 조합:** `Health`, `Damageable`, `Hackable`, `Interactable`, `Detectable` 같은 작은 컴포넌트를 조합해 적, 장치, 문을 만듭니다.
3. **이벤트로 느슨한 결합:** 시스템끼리 직접 참조하지 않고 이벤트(예: `OnEnemyKilled`, `OnAlertChanged`)로 통신합니다. 퀘스트와 평판 시스템은 이 이벤트를 듣기만 합니다.
4. **상태 머신:** 플레이어 이동 상태와 적 AI(경계 단계)는 명시적인 상태 머신으로 구현해 동작을 예측하고 디버깅하기 쉽게 합니다.
5. **저장 가능한 상태 분리:** 저장할 데이터(인벤토리, 평판, 퀘스트 진행, 월드 플래그)는 직렬화 가능한 순수 C# 클래스로 두고 JSON으로 저장합니다.

### 폴더 구조 (예정)
```
Assets/_Project/
  Scripts/
    Core/        # 이벤트 버스, 서비스, 유틸, 저장
    Player/      # 이동, 카메라, 입력, 상호작용
    Combat/      # 무기, 데미지, 투사체, 체력
    AI/          # 적 상태머신, 감지, 순찰
    Hacking/     # 스캔, 퀵핵, RAM, 장치
    Cyberware/   # 임플란트, 슬롯, 스탯 수정자
    Inventory/   # 아이템, 인벤토리, 상점
    Narrative/   # 대화, 퀘스트, 평판, 월드 플래그
    UI/
    Editor/      # 테스트 씬 자동 생성 등
  Data/          # ScriptableObject 에셋
  Prefabs/  Scenes/  Art/  Audio/
```

### 아트 전략
- 처음에는 **그레이박스**(단색 도형)로 모든 시스템을 완성하고 재미를 검증합니다.
- 그 뒤 에셋 스토어 팩(예: 사이버펑크 도시 모듈러 키트)을 입혀 룩을 만듭니다. 구매 여부는 그 시점에 사용자와 함께 정합니다.
- 네온 룩의 핵심은 모델링보다 **조명, 블룸, 안개, 반사, 데칼**입니다. 이는 코드와 설정으로 상당 부분 구현할 수 있습니다.
