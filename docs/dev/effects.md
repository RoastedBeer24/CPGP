# 원작 이펙트 (칼빛·불꽃·연기)

원작(아크나이츠: 엔드필드) 캐릭터의 공격 이펙트를 Godot로 옮긴 방식이다. 팬 사이트 studio.warfarin.wiki가
원작 이펙트를 웹에서 그리는 방식을 읽고, 같은 결과가 나오도록 직접 다시 만들었다(사이트 코드를 베끼지 않았다).
이펙트 자료(모델, 파티클 설정)는 원작 자산이라 저장소에 없고, 캐릭터 꾸러미 zip에만 있다(`docs/assets.md`).

## 자료가 흐르는 길
1. 사용자가 사이트에서 추출해 준 꾸러미(`!File/Endministrator_Extras/`)
   - `characters/{F,M}/animation_events.json`: 동작마다 몇 초에 어떤 이펙트를 어디에 띄우는지(`battle_effect_events`)
   - `characters/{F,M}/effect_catalog.json`: 이펙트 이름 → 이펙트 모델(glb)과 파티클 설정(`assets/data/*.json`)
2. `tools/extract_character_fx.py`가 게임이 쓰는 동작의 이펙트만 골라 캐릭터 zip의 `effects/`에 넣고, `fx.json`에
   이벤트(시작·끝 시각, 붙일 자리, 따라가는지)를 적는다.
3. 게임: `CharacterFx`가 동작 시작(`play`)에 맞춰 소리처럼 이펙트 이벤트를 예약하고, 시각이 되면 `FxEffect`를 띄운다.

## 코드 (`src/fx/`)
| 파일 | 하는 일 |
|---|---|
| `effect_library.gd` | zip에서 이펙트 glb와 파티클 JSON을 읽어 둔다(한 번만, 플레이어끼리 함께 씀). 노드마다 파티클 시스템을 이어 둔다 |
| `fx_effect.gd` | 이펙트 하나를 재생한다. 이벤트대로 놓고(아래), 끝 시각이 되면 남은 파티클까지 한 번에 지운다 |
| `fx_system.gd` | 파티클 시스템 하나를 CPU로 계산해 MultiMesh로 그린다 |
| `fx_curve.gd` | 파티클 설정의 곡선(허밋)·색 변화 계산 |
| `fx_material.gd` | 원작 재질 설정(VFXBaseV2)을 셰이더 재질로 바꾼다. 섞기·뒷면·깊이 조합마다 셰이더를 만든다 |
| `vfx_particle.gdshaderinc` | 파티클 정점 단계(그리기 정보 → 정점). 아래 셋이 함께 쓴다 |
| `vfx_base.gdshaderinc` | 원작 이펙트 셰이더(VFXBaseV2)를 다시 만든 것 |
| `vfx_refract.gdshaderinc`, `vfx_blur.gdshaderinc` | 재질 자료가 비어 있는 화면 왜곡(VFXRefract)·방사 흐림(VFXRadialBlur)을 비슷하게 만든 것 |

## 놓는 법 (이벤트)
- 붙일 뼈(`mount`)가 없으면 **캐릭터 모델의 원점(발밑)** 에 둔다. 원작 이벤트의 `path`는 원작 동작의 뿌리 이동(앞으로
  내딛는 거리)인데, 이 게임은 동작을 제자리로 묶고 플레이어가 직접 나아가므로 모델 원점이 곧 그 자리다.
- `move: follow`면 캐릭터를 따라가고, `stationary`면 나타난 자리에 남는다. `rot: stationary`면 나타날 때의 방향을 지킨다.
- `wep_R` 같은 자리가 있으면 그 노드에, 뼈 이름이면 뼈에 붙인다(`PlayerBody.effect_anchor`).
- 이펙트 시간은 동작 시간과 함께 흐른다(맞힌 순간 동작이 멈추면 이펙트도 멈춘다).

## 파티클 계산 (원작 파티클 시스템 중 쓰는 것만)
- 방출: 한꺼번에(burst), 초당(rateOverTime), 움직인 거리당(rateOverDistance). 1/60초 단위로 나눠 낸다. 최대 수를 지킨다.
- 처음 값: 수명·속도·크기(축마다)·회전(축마다)·색·중력, 모양(원뿔·상자·구·원·모서리 등)에서 나오는 자리와 방향.
- 움직임: 중력, 힘, 속도(직선·궤도·방사), 속도 제한(넘친 만큼 줄이기). 1/60초 이하로 쪼개 계산한다.
- 수명에 따른 변화: 크기, 회전(초당 회전을 쌓은 양), 색, 커스텀 데이터, 텍스처 시트 칸.
- 무작위 값은 시스템 씨앗과 태어난 순서로 정하므로 모든 피어에서 같은 모양이다.
- **좌표:** 파티클 설정은 유니티(왼손 좌표) 그대로다. 유니티 좌표로 계산하고, 그릴 때 X를 뒤집어 노드의 세계 변환을 곱한다.
  이펙트 모델(glb)과 이벤트 자세는 이미 glTF 좌표다.

## 그리기 (MultiMesh 인스턴스 하나 = 파티클 하나)
인스턴스 변환 자리에 그리기 정보를 담고 셰이더 정점 단계가 정점을 만든다.
- 메시·축 판: 세 축(크기·회전·좌표 뒤집기 포함)과 중심. 칼빛(검기 메시)은 대부분 이것이다.
- 화면 정면 판: 가로·세로·회전. 빛 번짐, 불빛.
- 늘어나는 판: 폭과 속도. 불꽃 줄기.
- 색 = 파티클 색, 커스텀 데이터 = x 메인 텍스처 밀기, y 샘플 슬롯 밀기, z 녹아 사라지는 정도, w 텍스처 시트 칸.
  칼빛이 휘두르는 방향으로 쓸려 나가고 끝이 타들어 가는 것이 이 값들이다.

## 셰이더 (VFXBaseV2)
메인 텍스처와 샘플 슬롯(최대 4개)을 합친다. 슬롯마다 왜곡·가중치·마스크·섞기·녹이기 역할이 재질 값으로 정해진다.
UV는 가중치·흐르는 속도·회전·타일링을 원작 순서대로 적용한다. 녹이기는 커스텀 데이터 z로 가장자리부터 사라진다.
섞기는 `_BlendMode` 0이면 알파, 1이면 더하기다. `_ZTest` 8은 다른 물체에 가려지지 않는다.

## 사이트가 그리지 않는 것을 채운 방법
- **극좌표 UV 충격파 고리**(`_USE_POLARUV`): 판의 가운데에서 잰 (각도, 거리)를 UV 가중치 z로 섞는다. 띠 그림이 고리가 되고,
  커스텀 데이터로 밀면 고리가 퍼진다.
- **화면 왜곡**(VFXRefract): 재질 자료가 비어 있어 직접 만들었다. 파티클 메시가 덮은 자리의 화면을 잡음 그림만큼 비튼다.
- **방사 흐림**(VFXRadialBlur): 재질 자료가 비어 있어 직접 만들었다. 판이 덮은 자리의 화면을 판 가운데 쪽으로 겹쳐 읽는다.
- **궁극기·대시 공격:** 원작 자료에 이펙트가 없어서 다른 동작의 원작 이펙트를 타격 시각에 맞춰 빌려 쓴다
  (`tools/extract_character_fx.py`의 `BORROWED`).

## 못 그리는 것
- 디더 알파(VFXDitherAlpha, 칼빛 뒤의 어두운 층 등 7개): 재질 자료가 비어 있고 어떻게 보여야 하는지 알 수 없다.

## 화면 확인
```bash
tools/capture.sh build/screenshots/fx 60,90,120 --single --autoplay=combo
```
`--autoplay=combo`는 로비에서 정해진 순서(기본 공격 5연속 → 회피 뒤 대시 공격 → 배틀 스킬 → 궁극기)를 되풀이하고,
`tools/capture.sh`는 그 프레임들만 PNG로 저장한다. 창은 화면 밖에 뜨고 소리·포커스·마우스를 가져가지 않는다.
